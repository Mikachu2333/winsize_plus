## 待决策项

### 1．超时前已经按下的鼠标事件可能尚未被处理

位置：`src/resident.rs` 的 `run`、`event`、`deadlines`；`src/input.rs` 的 `QueuedEvent`。

常驻循环先取最多 64 个输入事件，再检查到期时间。暂停计时发生在 UI 消费 `POINTER_DOWN` 时，而事件数据没有携带发生时间。若到期前的鼠标按下排在第 65 个及以后，旧计时可以先执行；相反，到期后发生但先于到期检查被消费的选择，也能重置计时。

这是排队条件下的顺序竞争；通常点击没有这种积压。建议用输入发生时间判定截止边界，并让截止前已排队的选择／按下事件先参与裁决。截止后输入不能重新激活到期会话。

**建议：调整。** 保持 10 s／3 s 不变，修正事件和到期判断的先后关系。备选是维持当前“以 UI 处理时间为准”。

### 2．滚动长提示会清除分区会话的超时

位置：`src/resident.rs` 的 `TIP_SCROLL` 分支。

该分支同时清除提示截止时间和 `preview_until`。使用特别长的分区名称使提示可滚动后，键盘滚动提示也会取消本应继续运行的 10 s 退出计时。这是旧提示行为与新选择计时共享状态的遗留耦合。

**建议：调整。** 阅读帮助可以保持显示；滚动分区操作提示只滚动文字，不修改分区选择计时。备选是明确把滚动也定义成暂停选择计时，但需要提示用户新的结束方式。

### 3．双击 Alt 的第二次松开仍有额外时限

位置：`src/input.rs` 的 `keyboard_inner`，`self.second` 与 Alt-up 分支。

第二次按下符合双击间隔时，代码取消长按计时；但进入选择会话仍要求第二次在 `double_ms` 内松开。第二次按住超过这个间隔，既不会按双击激活，也没有待执行的长按计时。

**建议：第二次按下被判定为双击时立即激活。** 这也减少一次等待松开的延迟。另一可选方案是仍在第二次松开时激活，但取消第二次按住时长的限制。

### 4．设置里的预览还保留两秒后隐藏其余框线的行为

位置：`src/preview.rs` 的 `follow`、`reset`；`src/settings.rs` 的 `render`、`escape`。

实际 Alt 操作使用 `interactive` 模式，悬停不会在两秒后隐藏其他区域。设置里的分区／框线／选择预览使用普通模式，仍会在同一区域停留两秒后聚焦该区域；此时第一次 Esc 恢复全部框线，第二次才关闭。因此两个界面的悬停和退出体验不同。

**建议：设置预览也持续保留全部框线，一次 Esc 关闭。** 若希望保留局部检查功能，可把“两秒聚焦”做成显式预览选项，而不是自动发生。

### 5．共边高亮的刷新既有重复，也有不及时

位置：`src/neighbors.rs` 的 `Hint::follow`；`src/resident.rs` 的 `MOVE` 分支。

相邻窗口快照最多每 100 ms 重算，但仅由鼠标移动触发。因此鼠标停着时，其他程序移动窗口后，旧边线可以一直保留到下次鼠标移动。另一方面，每次移动即使命中同一组边，也会先隐藏所有高亮，再重新设置颜色和显示，产生不必要的重绘。

**建议：调整。** 缓存当前显示的边和样式，只有变化时重绘；操作会话期间利用现有 100 ms 检查更新静止鼠标下的边。备选是以后再接窗口位置事件，减少轮询。

### 6．几类同步等待集中在 UI 线程，会推迟提示和取消响应

位置：`src/desktop.rs` 的 `position`、`restore`；`src/neighbors.rs` 的 `Drag::start`。

分区应用等待矩形稳定至少 60 ms，并最多验证 1200 ms；还原窗口最多等待 250 ms，特殊还原过程可再次等待。共边缩放开始时逐个查询参与窗口尺寸约束，每个查询上限 100 ms，多个响应较慢的窗口会累积等待。钩子线程仍采集输入，但 UI 消费这些输入和更新文字会被推迟。

这些等待承担正确性校验，不能简单删掉。**建议后续把窗口验证改为异步状态推进；共边尺寸查询采用整组时间预算，并在开始拖动前准备候选窗口信息。** 保留超时和结果检查。备选是维持现状，先对实际慢窗口收集延时数据再调整。

### 7．设置更改经过两段防抖后，会中断正在进行的选区

位置：`src/settings.rs` 的 `command`、`save`；`src/resident.rs` 的文件监听分支和 `load`。

开关／列表更改先等待 450 ms 保存，再等待常驻进程 160 ms 文件防抖，另有设置主计时器的调度粒度。配置真正载入时会取消输入状态并关闭预览。这样在选择期间，即使只改了字体或颜色，也会在设置操作之后延迟中断选区。

两段防抖分别用于保存和合并文件变动，有不同用途。**建议保留防抖，但区分配置影响：外观变更直接更新并保留选择和剩余时间；分区几何、绑定、排除项等变更取消选择。** 备选是所有配置变动推迟到当前会话结束后应用。

## 建议维持的现有规则

- 选择变更后重置 3 s，普通悬停不重置；按住鼠标时暂停、非选择操作完成后恢复剩余时间，和已确认的操作方案一致。
- 设置搜索 150 ms、防抖保存 450 ms、失败重试 2 s 各自对应不同工作，没有仅因数值相近而应合并的依据。
- 保存反馈的 100 ms 空白和 3 s／10 s 停留是独立显示规则；当前已防止旧计时消息提前显示新内容，也防止自动重试无限延长同一错误。
- 输入钩子的空闲状态核对与阻塞恢复、鼠标／键盘标注动画、文件监听重试，分别承担输入恢复、视觉反馈和配置可用性职责，不建议一并改成分区计时。
