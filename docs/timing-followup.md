## 计时审查项的处理

| 原编号 | 实施结果 |
| --- | --- |
| 1：输入队列与截止竞争 | 事件携带发生时间；积压输入先参加截止判断。截止前按下按发生时刻暂停，松开恢复剩余时间；截止后的选择输入不能重新激活过期会话。测试覆盖 70 个事件积压，超过原先每轮 64 个的处理额度。 |
| 2：滚动长提示清除选择截止 | 滚动只影响提示阅读，保持选择截止或暂停剩余时间。 |
| 3：双击 Alt 第二次按住过久失效 | 第二次按下符合双击间隔时立即激活；第二次松开不再重复激活或检查按住时长。 |
| 4：设置预览两秒聚焦 | 移除隐式聚焦计时，始终保留全部框线，一次 Esc 关闭。 |
| 5：共边高亮重复绘制和静止过期 | 缓存正在显示的矩形，位置不变不重绘；使用现有会话 100 ms 检查更新静止鼠标下的公共边。 |
| 7：外观重载中断选择 | 字体、颜色等外观更新重绘现有选择，保留目标、累计区域、暂停状态及截止时间；分区几何、按键、排除项等交互更新取消旧会话。 |

## 第 6 项：同步等待的测量

按“先测量慢窗口”的建议，在临时测试窗口上运行以下测试，保留原有校验逻辑。

| 场景 | 实测时间 |
| --- | ---: |
| 正常窗口应用分区并确认矩形稳定 | 76 ms |
| 目标窗口故意阻塞 300 ms 后应用分区 | 372 ms |
| 正常三个窗口的共边缩放启动 | 71 ms |
| 三个窗口各延迟 60 ms 返回尺寸约束 | 237 ms |

这些数值是本机该轮测试数据，不是性能上限。测试同时检查窗口最终矩形、三窗口横向联动、下方两窗口纵向分界联动和取消恢复。结果支持原审查的判断：尺寸查询的等待会累积，分区应用也有稳定性验证成本。进一步减少 UI 等待需要异步推进窗口验证及整组约束查询预算，不宜通过直接删掉等待实现。本轮按确认的测量方案交付数据。
