## 本机依赖验证方式

全局 Cargo 镜像未提供两个补丁，官方 sparse 索引连接超时。本次从 crates.io 官方 API 下载并验证补丁归档，将其加入工作区内的 `target/audit-vendor` 临时依赖副本；没有改变全局镜像配置。最终测试、Clippy 和 Release 构建使用同一份校验后的依赖：

```powershell
$sources = @(
    '--config', 'source.crates-io.replace-with="audit-vendor"',
    '--config', 'source.audit-vendor.directory="target/audit-vendor"'
)
cargo clippy --all-targets --locked --offline @sources -- -D warnings
cargo test --locked --offline @sources -- --test-threads=1
cargo build --release --locked --offline @sources
```

首次沙箱运行的输入测试缺少可用的桌面光标数据，GUI 测试收到访问拒绝；正常桌面权限下完整复跑通过。管理员实测还发现本机拒绝直接令牌创建进程，因此保留并验证了有时限的 Explorer 回退。
